A flow chains a project's tasks so their agent sessions start one after another. See [Automate with flows](/agents/flows) for what the connections do.

## `get_flow`

**Read-only. Allowed without asking.**

A project's flow: whether it's on, which project it starts after and which follow it, the tasks in the flow grouped by the agent that runs them, and for each task what it starts after and how, and where it runs. Also the open tasks outside the flow and the next ready task, as [`get_next_task`](/mcp/tools/sessions#get_next_task) finds it: a task after one that an agent handed back partly done or blocked isn't ready until that one is marked done or handed back again as done, or a newer session of it is marked finished.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `project` | string | yes | The project's id or name. |

Example:

```text
Flow for Organizer app (id organizer) · off: nothing starts on its own

Run by Claude Code:
- DEV-21 · In review · MCP server skeleton · after DEV-19 (auto) · runs in a terminal on DESKTOP-1
- DEV-22 · Todo · Start sessions from the app · after DEV-21 (manual) · runs in the Claude app on DESKTOP-1
- DEV-23 · Todo · Session tracking over MCP · after DEV-22 (same session) · runs in the Claude app on DESKTOP-1

Run by Codex:
- DEV-24 · Todo · Auto-planner for time blocks · after DEV-21 (auto) · runs in Codex cloud
```

## `connect_tasks`

**Changes data.**

Makes one task's session start after another's, within one project. Tasks not yet in the flow are added to it, the second one below the first. Calling it again for the same pair changes the mode.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | string | yes | The task that comes first. |
| `to` | string | yes | The task that starts after it. |
| `mode` | `auto`, `manual`, `same_session` or `at_time` | no | How `to` starts. Default `auto`. |
| `at` | date with time | for `at_time` | When the task may start. |

| Mode | `to` starts |
| --- | --- |
| `auto` | Automatically when `from` is finished. |
| `manual` | After the user marks `from` done. |
| `same_session` | In the same session as `from`, with the same agent. |
| `at_time` | At the set time, once `from` is finished. |

The mode belongs to the second task, so it applies to all connections leading to it. `same_session` also hands the second task to the first task's agent, and runs it where the first one runs.

Refused when:

* both tasks aren't in the same project (*Both tasks have to be in the same project; flows are per project.*);
* the connection would close a loop;
* either task is the user's own (`human`).

When the project's flow is off, the result reminds that nothing starts on its own until `update_project` sets `flow_on`.

## `disconnect_tasks`

**Deletes.**

Removes the connection that makes one task start after another.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `from` | string | yes | The task that comes first. |
| `to` | string | yes | The task that starts after it. |

## `add_to_flow`

**Changes data.**

Puts a project task on the flow canvas, below the rest of the flow, so an agent session can work on it. The agent is saved as the task's **Done by**. A task already on the canvas moves below the rest.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `task` | string | yes | The task key. The task must be in a project and not be the user's own. |
| `agent` | `claude` or `codex` | no | Defaults to the task's or the project's agent. |

## `remove_from_flow`

**Deletes.**

Takes a task off the flow canvas together with its connections. The task itself stays.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `task` | string | yes | The task key. |
