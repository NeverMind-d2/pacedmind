---
title: Connect Codex
description: Add PacedMind's MCP server to Codex's configuration and give it the access token, for Codex sessions PacedMind starts and for your own.
---

Codex reads its MCP servers from its configuration file, `~/.codex/config.toml`. PacedMind needs one entry there, for the Codex sessions it starts as well as for your own.

## Add the server

1. Open **Settings → Connect your agents** and select **Copy config** next to **Codex**. It copies:

   ```toml
   # ~/.codex/config.toml
   [mcp_servers.organizer]
   url = "http://127.0.0.1:4319/api/mcp"
   bearer_token_env_var = "ORGANIZER_TOKEN"
   ```

2. Open `config.toml` in the `.codex` folder of your user profile, such as `C:\Users\Anna\.codex\config.toml`, and paste the section at its end. Create the file if it doesn't exist.

Keep the name `organizer`: PacedMind's skills and first messages refer to the server by that name.

## Give Codex the token

The configuration doesn't contain the token itself. Codex reads it from the `ORGANIZER_TOKEN` environment variable:

* **Sessions PacedMind starts** get the variable from their terminal: nothing to do.
* **Your own Codex sessions** need it set. Copy the token from **Settings → MCP server** and store it for your Windows user:

  ```powershell
  setx ORGANIZER_TOKEN "org_..."
  ```

  `setx` applies to terminals opened afterwards. Open a new terminal before starting Codex.

After **Regenerate** in **Settings → MCP server**, run `setx` again with the new token. Sessions PacedMind starts pick up the new token on their own.

## Check the connection

Start Codex and ask something that needs the planner, such as *List my overdue tasks in PacedMind.* Codex should call the `organizer` tools, such as `get_overview` or `list_tasks`. If it can't, see [Troubleshooting](/troubleshooting#an-agent-cant-reach-pacedmind).

With the [agent skills](/skills) installed in `~/.codex/skills`, Codex also knows how to plan, triage and run project work with the tools.

## Remove the connection

Delete the `[mcp_servers.organizer]` section from `config.toml`, and the `ORGANIZER_TOKEN` variable from your user's environment variables.
