---
title: Automate with flows
description: How a project's flow decides which agent session starts after which, the four ways a session can start, when the flow starts sessions on its own, and how projects follow each other.
---

A **flow** chains a project's tasks so their agent sessions start one after another. Each task in the flow is one session, run by Claude Code or Codex. **Connections** decide the order: a connection from task A to task B means *B starts after A*, in one of four ways.

Flows are built in the [Flows](/views/flows) editor, or by an agent with `connect_tasks`. The dependencies drawn on the [Timeline](/views/timeline#dependencies) are the same connections.

## Ways to start

| Mode | In the editor | The next session starts | "Ready" means |
| --- | --- | --- | --- |
| **Automatically** | **Auto**, a solid line | As a new session, as soon as the task before it is finished. | The task before it is **In review** (the agent handed it back, not partly done or blocked) or **Done**. |
| **Manually** | **Manual**, a dashed line | As a new session, after you mark the task before it done. | The task before it is **Done**. |
| **In the same session** | **Same session**, a thicker line | In the same session: the agent carries on without stopping. | The agent handed the task before it back as done. |
| **At a set time** | The day and time, a dotted line | As a new session, at the set time, once the task before it is finished. | The task before it is **In review** (not partly done or blocked) or **Done**, and the time has come. |

A task the agent handed back **Partly done** or **Blocked** holds up every task after it until you mark it done, the agent hands it back again as done, or a newer session of the task is marked finished. See [Partly done or blocked](/agents/review#partly-done-or-blocked).

A new session runs where its task says: in a terminal or the agent's desktop app on your computer, or in the agent's cloud. See [Where a session runs](/agents/start-and-manage#where-a-session-runs).

**Automatically** lets agents work through a chain without waiting for review. **Manually** puts your review between two sessions. **In the same session** keeps the agent's context, for small steps that belong together. **At a set time** starts work at a chosen moment, such as the next morning.

A task with several connections leading to it waits for all of them, each checked by its own mode. New connections start as **Automatically**; choosing a mode under **Starts** in the editor sets it for all the connections leading to the task, and the editor points out when they differ.

## When the flow starts a session

With **Flow on**, PacedMind starts a task's session on its own when all of these hold:

* the task is **Todo** or **Backlog**;
* the task isn't yours;
* the task has at least one connection leading to it, none of them **Same session**, and every one is ready;
* the task has no running session.

PacedMind checks this when an agent hands a task back, when a session is marked finished, when you mark a task done, and every minute for timed connections. A session started this way notes *Started on its own* in the editor. Switching the flow on checks every task in the project the same way, so tasks that became ready while it was paused start right away. Adding a connection doesn't go back over tasks that are already ready: start those by hand, for example with the start button in the editor's panel.

A session in the cloud, or in a desktop app that isn't connected to PacedMind, can't hand its task back. **Mark finished** does it for the session, and the flow goes on from there. PacedMind notices finished Codex cloud tasks by itself.

**Flow on** is set per project: in the **Flows** header, in the **Roadmap**'s session panel, or in **Settings → Projects**. With the flow **Paused**, nothing starts on its own; connections still show the order, and sessions can be started by hand.

Tasks without connections leading to them, the first ones in a flow, don't start on their own, except when the project [starts after another one](#projects-in-sequence) and that one finishes, or has already finished when you switch the flow on. Start them yourself, for example with the start button in the editor's panel.

**Same session** connections don't depend on **Flow on**: the agent carries on in its session even while the flow is paused.

## Same-session chains

A **Same session** connection continues the previous task's session:

1. The agent finishes task A and calls `finish_task`.
2. PacedMind answers with task B and a new session id, and records *Continues session … in the same terminal*, or *in the same app session* in a desktop app.
3. The agent calls `start_task` for B and keeps working in the same session, with everything it learned on A.

One session can't switch agents or places, so a chain of same-session tasks runs with one agent, on one computer, in one place. Choosing **In the same session** hands the task to the agent and the place of the task before it; switching either on one task of the chain switches all of them. The editor draws a box around the chain, labeled *One Claude Code session*.

When the chain's terminal closes, every session in it that is still running closes too.

The next task continues only when the agent hands the task before it back as done with `finish_task`. After a partly done or blocked hand-back, it starts as a new session when you mark that task done. If the session is marked finished by hand instead, the next task starts as a new session. If the task is marked done by hand, or the terminal closes first, start the next task yourself. Cloud sessions can't continue one another, so a task after a cloud session starts as a new session.

## Projects in sequence

A project can **start after** another one, set in the **Roadmap**'s session panel (**Starts after**, **After this project**) or by an agent. When every task in the first project's flow is done or canceled, marking the last one done starts the next project's flow: PacedMind starts the sessions of its first tasks, those without connections leading to them, if that project's flow is on. If it's paused then, switching it on later starts them.

## Your own tasks

Tasks that are yours are never part of a flow. They can still have connections, drawn as dependencies on the **Timeline**, so they show what they wait for; PacedMind never starts a session for them.

## Build a flow step by step

1. Give the project a folder and a default agent in **Settings → Projects**, or bring your projects over with **Import from Claude and Codex** there.
2. Break the work into tasks with clear descriptions and **Done when** lists, which agents answer in their reports. See [Tasks](/concepts/tasks#done-when).
3. Open **Flows** for the project and drag the tasks onto the canvas in order. Dropping a task just below another connects it automatically.
4. Set how each session starts, and where it runs: select it and choose under **Starts** and **Runs in**. Use **Manually** where you want to review before the next step.
5. Select **Tidy up** to line the flow up, then switch **Flow on**.
6. Start the first session with the start button in its panel. The rest follows as the tasks finish.

An agent can do the same with the **pacedmind-projects** skill: it marks who does each task, connects the agent tasks with `connect_tasks`, and switches the flow on only when asked, because that lets PacedMind start agents on the computer. See [Agent skills](/skills).
